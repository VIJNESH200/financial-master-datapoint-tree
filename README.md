# Financial Master Datapoint Tree

A small reference tool for financial datapoints.

It shows the datapoint taxonomy of two industries:

- **GIND**
- **Bank**

For each industry you can look at:

- **Balance Sheet**
- **Income Statement**
- **Cash Flow Statement**

...plus a separate **Supplementary Items** list (EPS, DPS, book values, shares outstanding, dividend payout).

Every item in the tree shows its name and its datapoint code in `[brackets]`, for example `Revenue [Revenue]`.
Items with sub-items have a `+` / `−` button to open them.
Clicking an item opens the panel on the right, which shows the datapoint code, its definition, the statement, the industry, the full path and the direct children.

The whole project is plain HTML, CSS and JavaScript. There is no database, no server, no framework and nothing to install.

## How to run it

- No build system and no dependencies are required.
- The simplest way: open `index.html` in your browser (double-click the file).
- After you edit any file, save it and refresh the browser page to see the change.

## The files

```
index.html       → page structure  (what is on the page)
style.css        → appearance      (colours, spacing, layout)
taxonomyData.js  → financial taxonomy and datapoint hierarchy
definitions.js   → definitions for datapoint codes
script.js        → application logic
LICENSE          → MIT licence
```

**index.html** — The page structure. It contains the buttons (Industry and Financial Statement), the search box, the `Expand All` / `Collapse All` buttons, the tree area, the detail panel and the footer. It also loads the JavaScript files in the right order.

**style.css** — The visual appearance: colours, spacing, borders and layout.

**taxonomyData.js** — The financial taxonomy: every financial item and its hierarchy (which item is the parent and which items sit under it). **This is the file where financial items are added, removed or changed.**

**definitions.js** — The meaning of each datapoint code. **This is the file where definitions are added or changed.**

**script.js** — The application logic: drawing the tree, search, expand/collapse, the detail panel, the copy button and the industry/statement selectors. **Normally you do not edit this file** when you only change the taxonomy or the definitions.

**Load order matters:** `index.html` loads `taxonomyData.js` and `definitions.js` first, and `script.js` last, because the logic reads the data and the definitions. This is already set up correctly — you only need to remember it if you rename a file.

## How to add a datapoint

Open `taxonomyData.js`. All the data is inside one object called `financialData`, grouped like this:

```
gind → balanceSheet / incomeStatement / cashFlow
bank → balanceSheet / incomeStatement / cashFlow
supplementaryItems   (one flat list, shown as "Supplementary Items")
```

Find the list where the new item belongs — for example the Bank Income Statement — and add the new item inside that list.
An item is written like this:

```js
{
    name: "Cash & Cash Equivalents",
    datapoint: "Cash_And_Cash_Equivalents"
}
```

- `name` = what users see on the webpage.
- `datapoint` = the actual datapoint code. It is shown in blue brackets and is used by the search, the copy button and the definitions.
- `children` = the items that sit underneath this item (see the next section).

A few practical rules:

- Put a comma after every item, except after the last item in a list.
- Copy the style (indentation, quotes) of the items that are already around it.
- Two balance sheet items also have a line such as `isSide: "assets"`. Leave it exactly as it is — it only affects styling.
- Save the file and refresh the browser.

## How to add a datapoint with children

If an item has sub-items, it gets a `children` list, and a `+` / `−` button appears next to it in the tree:

```js
{
    name: "Current Assets",
    datapoint: "Current_Assets",
    children: [
        {
            name: "Cash & Cash Equivalents",
            datapoint: "Cash_And_Cash_Equivalents"
        }
    ]
}
```

An item can have its own `datapoint` **and** children at the same time. `Revenue [Revenue]` is an example: it has its own code and also has two children.

## The basic rule: { } and [ ]

- `{ }` (curly brackets) = **one item**. Everything between them describes a single datapoint: its name, its code and its children.
- `[ ]` (square brackets) = **a list of items**. `children: [ ... ]` is simply the list of items that sit under this item.
- The tree is built from these lists: the top-level list is the main tree, and each `children` list is one level deeper.

You do not need to know any other JavaScript to maintain the taxonomy.

## How to add or change a definition

Open `definitions.js`. Each line is one datapoint code followed by its explanation:

```js
Revenue: "Income generated from the company's ordinary business activities during the period.",
```

- The key on the left (before the colon) must be **exactly the same as the `datapoint` code** in `taxonomyData.js`.
- The text in quotes is what appears in the detail panel.
- Keep it to one or two short sentences.
- If a code has no definition, the detail panel shows "Definition not available."
- If the same code is used in more than one statement, one definition is enough — the key is shared.

## Important

- If you are only changing financial datapoints, do **not** edit `script.js`.
- If you add a new datapoint, add its definition in `definitions.js` as well.
- Preserve the existing datapoint code unless you intentionally want to change the code used by the application, because search, copy and definitions all match on that code.
- Save the files and refresh the browser to see your changes.
- If the page stops working after an edit, the most common cause is a missing comma, a missing `}` or `]`, or a missing quote `"`. Undo your last change and add it again carefully.
